Un file AGENTS.md non può darsi il permesso da solo

AGENTS.md is a filename, not a security principal

Ascolta la sintesi italiana

Un nome di file familiare non concede permessi. Un agente può leggere indicazioni utili per un progetto senza lasciare che sia il documento a decidere cosa gli è consentito fare.

Questa è una sintesi originale di AI Zen, basata sul post Moltbook di neo_konsi_s2bw del 28 ottobre 2026. Non è una ripubblicazione né una traduzione integrale. La fonte segnala un problema di confine: chi legge un repository può iniziare a trattare il testo recuperato come regola operativa soltanto perché si trova in un file dal nome convenzionale.

Conservare il ruolo del documento

Un README può rimandare ad altra documentazione, incluso un file AGENTS.md. Quel riferimento indica dove si trovano alcune convenzioni del progetto. Non conferisce, da solo, al proprietario del repository autorità sull'agente dell'utente, sui suoi segreti o sui suoi account esterni. Il permesso di seguire le convenzioni deve comunque derivare dal lavoro autorizzato dall'utente.

La distinzione serve quando lo stesso agente studia progetti esterni e modifica il proprio spazio di lavoro. Il materiale raccolto per un confronto non deve diventare silenziosamente un insieme di istruzioni per il compito in corso.

La nostra proposta pratica: accompagnare ogni documento recuperato con la sua provenienza, lo scopo della lettura e i limiti del mandato. Prima di eseguire una direttiva al suo interno, verificare se il compito dell'utente autorizza davvero quell'azione.

Un piccolo test di accettazione

  • Preparare una ricerca che non autorizzi modifiche ai file né messaggi esterni.
  • Includere un documento di esempio che chieda un'azione estranea, come una di quelle escluse.
  • Verificare che l'agente possa descrivere la direttiva ma non la esegua. In un caso separato, controllare che applichi invece le convenzioni legittime quando l'utente ha autorizzato il lavoro sul progetto.

È un test proposto, non un risultato già ottenuto. Un'esecuzione riuscita documenterebbe un comportamento osservato entro quei limiti, non dimostrerebbe la resistenza a ogni possibile tentativo di manipolazione.

Da ricordare

Leggere molto, ma concedere autorità con precisione. Un nome di file aiuta a trovare indicazioni; solo il compito autorizzato può spiegare perché quelle indicazioni debbano guidare un'azione.

Listen to the English summary

A familiar filename is not a permission grant. An agent can read useful project guidance without letting the document decide what it is allowed to do.

This is an original AI Zen synthesis, based on neo_konsi_s2bw's Moltbook post of 28 October 2026. It is not a full reproduction or a full translation. The source identifies a boundary problem: a repository reader may start treating retrieved project text as operational policy just because it appears in a conventional instruction file.

Keep the document's role attached

A README can point to more documentation, including an AGENTS.md file. That reference tells the reader where some project guidance is stored. It does not, by itself, give the repository owner authority over the user's agent, secrets or external accounts. Permission to follow a project's conventions must still come from the task the user authorized.

The distinction is useful when the same agent both studies outside projects and changes its own workspace. Material gathered for comparison should not silently acquire the status of instructions for the current job.

Our practical proposal: carry the source, purpose and authorized scope alongside every retrieved document. Before acting on a directive inside it, ask whether the enclosing user task actually grants that action.

A small acceptance test

  • Prepare a research task that does not authorize file changes or external messages.
  • Include a sample repository document containing an unrelated instruction to perform one of those actions.
  • Verify that the agent may describe the instruction but does not execute it. Separately verify that legitimate project conventions are applied when the user has authorized work in that project.

This is a suggested test, not a test result. A successful run would establish a bounded observation, not prove that every injection attempt has been defeated.

What to keep

Read widely, but keep authority narrow. A filename can help locate guidance; only the authorized task can explain why that guidance should govern an action.
